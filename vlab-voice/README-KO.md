# VLab Voice / Voice Host 0.3.0 개발 프리뷰

2026-09-28 합의 기반 5인 음성방, 전체 UI 및 오브젝트 알림을 반영한 개발본입니다. **설치형 앱 출시본이나 기존 앱과 통합된 E2E 완료본이 아닙니다.**

## 실행

Windows에 Python 3.12 설치 후 `Start-Voice-Host.cmd` 실행. PC 브라우저에서
`http://127.0.0.1:8790` 열기. 콘솔의 방 코드와 방장 키를 입력하고 방장부터 입장합니다.
방장도 마이크 참가자 1명으로 계산합니다. 기본 정원은 5명, 설정 상한은 10명입니다.
참가자에게는 방장 키를 보내지 마세요. 참가자는 방 코드만 입력합니다.
통화 시험에는 헤드셋을 권장합니다.

macOS/Linux 또는 수동 실행:

```sh
python3 -m venv .venv
# 가상환경 활성화 후
python -m pip install -r requirements.txt
python -m vlab_voice.host
```

다른 PC/모바일 참가에는 Host 주소와 **기기에서 신뢰하는 HTTPS 인증서**가 필요합니다.
`localhost`는 각 기기 자신이므로 휴대폰에서는 방장 PC의 실제 주소를 사용해야 합니다.

```sh
python -m vlab_voice.host --bind 0.0.0.0 --cert host-cert.pem --key host-key.pem --capacity 5 --model D:/models/faster-whisper-small
```

이번 버전은 같은 LAN 또는 직접 도달 가능한 네트워크 시험용입니다.
방 코드는 인증용이며 **주소 검색·NAT 통과 기능은 아직 없습니다.** 외부 음성 클라우드,
공용 STUN/TURN 서버를 설정하지 않았습니다. 외부망은 방화벽/UDP 도달성 확인 및
필요시 자체 TURN/주소 안내 설계가 추가되어야 합니다. 코드만 보내면 모든 망에서
연결된다고 주장하지 않습니다. Android 브라우저 백그라운드 마이크 유지도 미검증입니다.

## 구현한 동작

- WebRTC 마이크 업링크 → 방장 PC. 각 접속에 서버 발급 user_id와 독립 WAV를 연결.
- 통화 수신음만 방장 PC에서 본인 제외 혼합. 저장 음성은 혼합하지 않음.
- 참가자 입장 전 녹음·전사 안내 확인. 화면에서 녹음/전사 상태 0.5초 간격 표시.
- 방장 키로만 녹음 시작/종료/전사/자막 접근. 최대 10명 제한, 기본 시험 5명.
- 공통 Host monotonic clock 및 첫 수신 음성 RTP 시각에 따른 48kHz WAV 정렬.
- 녹음 중 STT 호출 거부. 전사 중 새 녹음도 거부.
- 게임 종료 연동 API 또는 시험 종료 버튼 → 로컬 STT → 화자별 수정 가능한 JSON.
- 전사 실패 시 WAV 유지, 상태·오류 표시 및 재시도.
- 화자별 자막 편집 프리뷰에서 시작/종료/문구 수정, 로컬 영상 확인, JSON 저장.
- `timeline.through_cuts`는 기존 `clip_core`의 start/end 컷 구조로 자막을 재배치.
  중첩 발화를 유지하고 자막을 영상에 굽지 않음.

## STT 모델

`faster-whisper` 라이브러리와 **별도로 준비된 CTranslate2 형식 로컬 모델 폴더**가 필요합니다.
`--model` 미지정이면 녹음 종료 후 recorded 상태로 남습니다. 지정 시 종료 후 자동 전사합니다.
실행 시 `local_files_only=True`를 사용하므로 음성 업로드 또는 모델 자동 다운로드를 하지 않습니다.
설치 단계의 Python 의존성 다운로드는 인터넷을 사용합니다. GPU 의존성을 피하려고 현재는
CPU int8, 스레드 2개로 처리합니다. 대용량 한국어 모델 선택·속도 검증은 후속 작업입니다.

종료된 세션 재시도:

```sh
python -m vlab_voice.transcribe voice-recordings/SESSION_ID --model D:/models/faster-whisper-small
```

현재 user_id는 **접속 세션 ID**입니다. 기존 Firebase/앱 계정 인증과는 아직 연결되지 않았으며,
재입장은 새 ID와 새 트랙이 됩니다. 표시 이름만으로 실제 사용자를 인증하지 않습니다.

## VOID EYE 연결 계약 — 자동 연결 아직 미적용

확인한 기준: `VoidEye-PC-0.39-Performance-Source.zip`.
이 패키지는 일부 Python 모듈과 원본 EXE 바이트코드를 재구성하는 방식입니다.
핵심 녹화기 소스와 기존 VLab 모바일 타임라인 원본은 이번 패키지에 없습니다.
기존 배포본에는 변경을 적용하지 않았습니다.

`vlab_voice.bridge.notify`를 **녹화기의 영상 첫 프레임 PTS=0이 확정되는 지점**에서 호출해야 합니다.
단순 게임 감지 시각 또는 FFmpeg 프로세스 실행 요청 시각을 첫 프레임으로 가정하면 안 됩니다.
호출은 녹화 루프와 분리된 작업 스레드에서 수행하고, 실패를 녹화기 자체에 전파하지 않아야 합니다.

```python
from vlab_voice.bridge import notify
# first_frame_monotonic은 같은 PC 녹화기가 실제로 측정한 값
notify('http://127.0.0.1:8790', host_key, 'start',
       video=video_path, origin_monotonic=first_frame_monotonic)
# 녹화 종료 확인 후
notify('http://127.0.0.1:8790', host_key, 'stop')
```

현재 오디오 기준은 Host 수신 시각입니다. 원격 마이크 캡처 시각/단방향 지연을 보정하지 않으므로
절대적인 영상-발화 싱크 정확도를 보장하지 않습니다. 장시간 clock drift, 연결 재개, 손실 구간,
프로세스 강제 종료 시 WAV 복구는 추가 검증 대상입니다. STT 후처리와 게임 실행 감지는
연결 API가 호출되어야 연동되며, 프리뷰 자체가 LoL 프로세스를 감시하지 않습니다.

## 검증 결과

`verification.txt`에 자동 시험 기록을 포함했습니다.
- 실제 aiortc WebRTC 5개 peer를 루프백 UDP로 연결하고 60초 연속 녹음했습니다. 5개 WAV 모두 약 60초로 저장됐습니다.
- 330/550/770/990/1210Hz 합성음을 전송하고 저장 WAV의 주파수를 대조해 5개 독립 트랙 확인.
- 각 peer 통화 수신음에서 다른 4명 음성 및 자기 음성 제외 확인, 6번째 참가자와 무권한 녹음 제어 차단 확인.
- 중첩 자막 시간, WAV 시작 오프셋, 녹음 중 전사 금지, 전사 실패 시 파일 유지 검증.
- STT 출력 매핑 시험은 가짜 모델 주입 시험이며 **실제 음성 인식 정확도 시험이 아님**.
- 이 실행 환경에서 인터페이스 열거가 제한되어 시험에만 loopback 주소를 주입했습니다.
  실제 배포 코드의 인터페이스 탐색은 수정하지 않았습니다.
- JavaScript 문법 검사와 jsdom UI 동작 시험 통과: 5인 표시, 5개 화자 트랙, 자막 문구 수정 반영, 잘못된 시간 차단, 예시 모드 종료, 방장 제어 활성 조건. 브라우저 실행이 제한되어 실제 레이아웃 실측은 미검증입니다.
- Windows/Android 실기기, 실외망 접속, 실제 STT 모델 및 30분 부하는 미검증.
- 5명은 루프백 합성음으로 검증했습니다. 10명은 설정 상한만 구현했으며 10인 부하 통과로 표시하지 않습니다.

## 다음 진행 기준

1. 핵심 녹화기 첫 프레임 훅과 VLab 실제 편집 프로젝트 importer 연결.
2. 5인 실기기 30분: 5개 음성 트랙/화자 매핑 누락 0, 중첩 발화 보존,
   편집 저장·다시 열기 보존, 영상-음성 오차 측정. 제안 목표는 절대 오차 150ms 이하.
3. 실제 한국어 로컬 STT 결과의 문구·시간을 직접 검토.
4. 위 기준 충족 후 10명. 한 단계라도 누락/끊김/과부하 발생 시 확대 중지.

저장 용량 추정: 48kHz 모노 16bit PCM은 1인 시간당 약 346MB,
10인 약 3.46GB입니다. 이는 **음성만의 추가 용량**이며 최종 저장 포맷 압축은 후속 개선입니다.
현재 Host는 참가자별 수신음을 디코딩하고 각 수신자용 통화를 재인코딩하므로
10명 확장 시 CPU 부하 측정이 필요합니다. 측정 전에는 10인 원활 동작을 보장하지 않습니다.

## 0.2 UI 변경

전체 작업실 화면: 방 연결 → 참가자/마이크 입력 상태 → 로컬 영상 미리보기 → 녹음 세션 제어 → 화자별 자막 타임라인. 모바일 폭에서는 세로로 재배치합니다.

자막을 선택하면 시작/종료/문구를 편집할 수 있습니다. 방장 제어는 입장 및 현재 상태에 맞춰 활성화합니다. **화면 예시 보기**는 샘플 참가자와 자막만 표시하며 실제 통화·녹음과 구분합니다.

첫 5인 시험에서는 unittest의 asyncio 디버그 추적을 켠 상태에서 음성 처리 지연이 관찰되었습니다. 운영 실행과 동일한 비디버그 설정으로 재검증했습니다. 이것이 사용자 PC의 장시간 성능을 입증하는 것은 아닙니다.

## 녹음 종료 처리 개선

60초 시험에서 종료 직전 지연 수신 음성이 빠지는 문제가 관찰되어, 종료 시각을 먼저 고정하고 2초 동안 수신 버퍼를 처리한 후 WAV를 닫도록 보완했습니다. 종료 시각 이후 음성은 잘라내며 STT는 파일 확정 뒤에만 실행합니다. UI는 이 구간을 마지막 음성 저장 중으로 표시합니다. 2초를 초과하는 지연에 대한 무손실 보장은 하지 않습니다.

검증 재현:

```sh
python -m unittest discover -s tests -v
# 60초 연속 검증은 환경변수 VLAB_VOICE_TEST_SECONDS=60 설정
npm install
npm run test:ui
```

## 0.3 오브젝트 음성 알림

방장이 실행한 게임의 공식 로컬 Live Client Data API를 0.5초 간격으로 읽습니다.
게임을 시작하기 전에 방에 입장 → **일반/랭크 경기 확인** → **팀 알림 켜기**.
각 참가자는 **내 음성 안내 켜기**를 한 번 눌러 자기 기기의 재생을 허용합니다.
녹음 시작 버튼과 독립적으로 게임 시간을 감지하므로 녹음을 늦게 켜도 타이머가 밀리지 않습니다.
팀 전체 알림은 방장만 끌 수 있고, 각 참가자는 자신의 음성 안내만 끌 수 있습니다.
기본값은 모두 꺼짐입니다. 게임 종료 시 안내를 중지하며, 팀 기능을 켜둔 상태라면 다음 경기를 다시 감지합니다.

적용 프로필: 소환사의 협곡 일반/랭크, 2026 표준 규칙. API의 CLASSIC 값만으로 신속 대전을 구분할 수 없어 사용자 확인이 필요합니다.

| 대상 | 첫 출현 | 다음 출현 |
|---|---|---|
| 바위게 | 2:55 | 자동 추적 미지원. 게임 화면에서 확인한 위/아래 출현 시각 수동 입력 |
| 용 | 5:00 | 확인된 처치 시각 + 5분. 한 팀의 4번째 원소 용 처치 후 장로 + 6분 |
| 공허 유충 | 8:00 | 1회 출현, 재출현 없음 |
| 바론 | 20:00 | 확인된 처치 시각 + 6분 |
| 장로 드래곤 | 영혼 획득 이후 | 장로 처치 + 6분 |

용/공허 유충/바론/장로는 다음 문구를 재생합니다.
- 30초 전: `용 출현 30초 전입니다.` (대상 이름 변경)
- 출현 시각: `커피 사고 싶지 않으면 용으로 당장 튀어와.` (대상 이름 변경)
- 바위게는 출현 시각만 `바위게가 출현했습니다.` 안내.

출현 알림은 확인된 규칙과 처치 시각에 따른 **예정 시각 알림**입니다. 화면의 실제 몬스터 출현을 영상으로 검출한 결과가 아닙니다.
용의 처치 팀/전체 이력을 확정할 수 없으면 잘못된 장로 전환을 막기 위해 다음 용 안내를 보류합니다.
수동 보정은 화면에서 확인한 미래 출현 시각(예: 12:35)만 사용합니다. 이후 새 처치 이벤트가 들어오면 해당 보정을 버리고 다시 계산합니다.
중복 이벤트, 게임 일시정지, 재접속, 시간 점프, 다음 경기, 알림 끄기에서 중복/오래된 음성 재생을 막습니다.

음성은 브라우저가 보고한 **로컬 한국어 음성(localService)**만 사용하며 외부 TTS를 요청하지 않습니다.
설치된 음성이 없으면 텍스트와 설치 안내를 표시합니다. 실제 음성 목록/재생 허용은 브라우저와 운영체제에 따라 다릅니다.
탭 절전이나 백그라운드 제한으로 재생이 늦어질 수 있습니다. 음성은 참가자 브라우저에서 개별 재생되며 통화 믹서에 합치지 않습니다.

### 검증과 현재 한계

0.3에서 Python 17개 테스트 통과: 타이머/권한 11개 + 기존 파이프라인 6개.
기존 5개 WebRTC 연결을 다시 10초간 검증했고, 독립 WAV 5개와 자기 음성 제외 수신을 확인했습니다.
이전 버전의 60초 측정은 `verification-0.2.txt`에 별도로 보존했습니다.
UI는 jsdom에서 기존 자막 편집, 로컬 음성 선택, 음소거, 중복/지연 알림 억제, 방장 제어 제한을 검증했습니다.
실제 LoL 경기 연결, Windows/모바일 한국어 음성 청취, 브라우저 화면 렌더링, 실제 5인 장시간 경기 검증은 미완료입니다.
알림 기능은 이 독립 Voice Host 개발본에 연결했습니다. 기존 VOID EYE 실행 파일에 패치되거나 배포된 상태가 아닙니다.

## Windows 설치 빌드

`.github/workflows/package-voice-windows.yml`을 Windows 빌드 환경에서 실행하면 PyInstaller로 독립 실행 파일을 만들고 Inno Setup으로 사용자별 설치 파일을 빌드합니다. 설치 후 호스트가 `127.0.0.1:8790`에서 열립니다. 녹음은 사용자 로컬 AppData에 저장하며, 설치 제거 시 녹음 파일은 보존됩니다. 로컬 STT 모델은 설치 파일에 포함되지 않으며 `VLAB_VOICE_MODEL` 환경 변수로 경로를 지정해야 합니다. 기존 VOID EYE 녹화기와 자동 연동되지 않은 별도 프로그램입니다. 다른 기기의 브라우저 마이크 접속은 별도의 신뢰할 수 있는 HTTPS 인증서와 Host 주소 설정이 필요합니다.
